## 1. 项目内容解析

### 1.1 要解决什么问题

账号租赁平台日常运营面临：

- 业务数据分散（游戏 / 账号 / 订单 / 退款 / 日指标），查数依赖人工 SQL；
- SOP、退款、定价、风控等规则散落文档，难以及时对照；
- BI 能看数，但「为何异常、按规则怎么处理」缺少闭环。

本系统目标是把 **业务数据 + 运营知识 + Multi-Agent** 串成：

```text
运营人员 → 看板 / 自然语言
         → Supervisor 路由
         → 数据 Agent（NL2SQL + MCP）/ 知识 Agent（RAG）/（后续）异常·策略 Agent
         → 可追溯结论（建议阶段不写业务库）
```

### 1.2 技术架构（已落地）

| 层级 | 选型 | 本仓库落点 |
|------|------|------------|
| 前端 | Vue + Vite + ECharts | `frontend/` 驾驶舱 + AskDialog |
| 后端 | FastAPI `:8888` | `backend/app/` |
| 数据 | PostgreSQL | `ops_*` / `sys_*` / `ai_*` |
| 工具 | MCP + SQL Guard | `backend/app/mcp/` |
| Agent | LangGraph Supervisor + NL2SQL + Knowledge | `backend/app/agent/` |
| RAG | Embedding + Milvus Lite + PG 切片 | `backend/app/rag/`、`data/knowledge/` |
| 模型 | OpenAI Compatible（Qwen / DeepSeek 等） | `.env` + `agent/llm.py` |

**原则（不变）：** AI 默认只读；策略只建议不写库；前期本机跑通，Docker / Redis / LangSmith 后置。

### 1.3 当前仓库能力地图

```text
frontend/
  DashboardView     运营驾驶舱（指标 / 趋势 / 排行 / 详情）
  AskDialog         智能 / 问数 / 问规则（默认 SSE 流式）

backend/app/
  api/v1/           health · dashboard · mcp · knowledge · agent
  services/         看板聚合查询
  mcp/              只读工具 + sql_guard + stdio server
  agent/            nl2sql · knowledge · supervisor · llm · sse
  rag/              chunker · embeddings · vector_store · ingest · retriever
  models/           业务表 + ai_session/task/execution（表已建，业务未接）

data/knowledge/     模拟 SOP / 退款等 Markdown
```

## 3. 后续工作规划（分阶段）

> 原则：小步可验收；先补齐 SRS P0 缺口与演示可信度，再扩 P1 Agent；工程化最后。  
> 每一阶段开工前再拆成独立 Implementation Plan（`docs/superpowers/plans/`），本文件做总路线图。

### Phase A — 会话 / 任务落库与回看（F09）【已完成 2026-09-28】

**目标：** 每次问答可落库、可按 session/task 查询轨迹；与现有 SSE 兼容。

| 项 | 内容 |
|----|------|
| 范围 | 写入 `ai_session` / `ai_task` / `ai_agent_execution`；脱敏 SQL/摘要；API：创建会话、提问、查任务/执行记录；前端可展示路由与执行步骤 |
| 验收 | 问一句 → DB 有 task + execution；失败也能看到 error；前端「查看执行步骤」可拉轨迹 |
---

### Phase B — 登录与最小权限（F01）【已完成 2026-09-28】

**目标：** JWT 登录；管理员 / 运营 两角色；看板与 Agent 接口鉴权。

| 项 | 内容 |
|----|------|
| 范围 | 登录 API、前端登录页、接口依赖鉴权；演示账号 seed |
| 验收 | 未登录 401；运营可看板+问答；管理员可知识入库 |
---

### Phase C — 异常分析 Agent（F04）【已完成 2026-09-28】

**目标：** Supervisor 增加 `anomaly` / `anomaly_knowledge`；对 GMV/订单/出租率/退款率做窗口对比与游戏下钻。

| 项 | 内容 |
|----|------|
| 范围 | `services/anomaly.py` 检测；`agent/anomaly.py` 作答；Supervisor 路由与流式；`POST /agent/anomaly` |
| 验收 | 「最近出租率为何异常」可出数据依据；带规则问句走 anomaly→knowledge 汇总 |
---

### Phase D — 策略分析 Agent（F06）【已完成 2026-09-28】

**目标：** 结合数据 +（可选）知识，输出运营建议；**禁止写业务库**。

| 项 | 内容 |
|----|------|
| 范围 | `agent/strategy.py`；Supervisor `strategy` / `strategy_knowledge`；`POST /agent/strategy`；前端预设与「仅建议」提示 |
| 验收 | 建议可读、可引用指标/知识；写意图 reject；回答含「不自动修改业务数据」 |
| 依赖 | Phase C（复用窗口指标快照） |

---

### Phase E — 检索与查询质量增强（RAG + NL2SQL 已完成 2026-09-28）

**目标：** 降低「能跑但不准」的演示风险。

| 项 | 内容 |
|----|------|
| RAG | ✅ Hybrid（向量+BM25）+ RRF；可选 Rerank（`RAG_RERANK_ENABLED`）；无命中仍走知识 Agent 固定话术 |
| NL2SQL | ✅ Schema 模板强化、缺 `WITH` 修复、结构自检、失败重试 1 次（生成/执行） |
| Demo | ✅ `python -m scripts.smoke_e2e`（对照 docs/03：看板 / 问数 / 知识 / 异常 / 策略 / 拒绝写 / 轨迹） |

## 6. 风险与约束

- **模型不稳定：** NL2SQL / 路由依赖 LLM，必须保留 SQL Guard 与 reject；落库便于复盘。
- **安全：** 全阶段禁止 Agent 写业务表；策略输出不得触发 UPDATE/DELETE。
- **范围蔓延：** 异常告警推送、真实平台对接、生产级 RBAC 不在第一阶段。
- **环境：** 继续以本机 PostgreSQL + Milvus Lite + 外网 LLM 为主路径。
