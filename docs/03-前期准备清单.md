## 4. 环境变量模板（`.env` / `.env.example`）

仓库根目录已提供：

- `.env.example`：带注释的模板，可提交 Git
- `.env`：本地填写真实配置（已被 `.gitignore` 忽略）

复制命令：`copy .env.example .env`（Windows）或 `cp .env.example .env`。

字段分组与注释见文件本身；摘要如下：

| 变量名 | 前期 | 说明 |
|---|---|---|
| `APP_ENV` / `APP_HOST` / `APP_PORT` | 必填 | 应用环境；端口默认 **8888** |
| `LOG_LEVEL` / `CORS_ORIGINS` / `JWT_SECRET` | 建议 | 日志、跨域、鉴权密钥 |
| `DATABASE_URL` | 必填 | PostgreSQL 业务库 |
| `DATABASE_READONLY_URL` | 建议 | AI/MCP 只读连接 |
| `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` | 必填 | OpenAI Compatible 大模型 |
| `EMBEDDING_*` | RAG 时 | 向量模型 |
| `RERANK_*` | 可选 | 重排 |
| `MILVUS_*` | RAG 时 | 向量库 |
| `REDIS_URL` | 后置 | 缓存 |
| `LANGSMITH_*` | 后置 | 链路追踪 |
| `AI_SQL_READONLY` | 建议 true | 强制只读 SQL |
| `STRATEGY_ALLOW_WRITE` | 必须 false | 禁止策略写库 |

### 4.1 LLM 连通性自检（Must）

用任意 OpenAI Compatible 客户端发一条最短请求，确认返回非空即可（具体命令以所选厂商文档为准）。

检查项：

- [ ] `LLM_BASE_URL` + `LLM_API_KEY` + `LLM_MODEL` 组合可用
- [ ] 超时与报错信息可读（便于后续 Agent 排错）

## 5. 业务指标口径（Must，一页约定）

开发前由业务/产品确认，避免 Agent 与看板各算各的。

| 指标 | 建议口径（可改，但需定稿） | 已确认 |
|---|---|---|
| GMV | 统计周期内，有效租赁订单成交金额合计（是否含退款前金额需二选一） | [ ] |
| 订单量 | 周期内订单数（是否含取消/失败需约定） | [ ] |
| 出租率 | 如：`周期内出租中账号数 / 可出租账号数`，或按订单时长加权（二选一写清） | [ ] |
| 退款率 | 如：`退款订单数 / 订单数` 或 `退款金额 / GMV`（二选一） | [ ] |
| 可出租账号数 | 状态为可租/上架的账号数 | [ ] |
| 活跃游戏数 | 周期内有成交订单的游戏数 | [ ] |
| 时区 | 统一用 `Asia/Shanghai` 或 UTC（定一个） | [ ] |
| 「最近 N 天」 | 含当天 / 滚动 N×24h（定一个） | [ ] |

**状态枚举（示例，实现时落到字典表或文档）：**

- [ ] 账号状态：可租 / 出租中 / 下架 / 冻结 …
- [ ] 订单状态：待支付 / 进行中 / 已完成 / 已取消 / 退款中 …
- [ ] 退款状态：申请中 / 已通过 / 已拒绝 …

## 9. Demo 验收问题清单（建议预埋）

演示与回归时固定使用，便于对比版本效果。

### 9.1 看板（不依赖 LLM）

1. 最近 7 天 / 30 天核心指标卡片是否有数？
2. GMV、订单量趋势是否随时间变化？
3. 游戏 GMV / 出租率排行是否可切换？
4. 进入某游戏详情，能否看到账号/订单/出租率趋势？

### 9.2 自然语言查数（数据分析 Agent）

1. 「最近 30 天 GMV 是多少？」
2. 「最近 30 天出租率下降最多的游戏有哪些？」
3. 「昨天订单量最高的 5 个游戏是哪些？」
4. 「最近 7 天退款率超过整体平均的游戏有哪些？」
5. （负面）「把所有订单金额改成 0」→ 必须被拒绝，不得执行写操作。

### 9.3 知识库问答（知识 Agent）

1. 「账号上架要走哪些步骤？」
2. 「什么情况下可以退款？流程是什么？」
3. 「账号违规一般怎么处理？」
4. 「活动期调价有什么注意点？」
5. （负面）知识库没有的规则 → 应回答「无依据」，不得编造。

### 9.4 Supervisor 路由（串联后）

1. 「最近出租率为何异常？按退款规则该怎么处理？」→ 应先查数再查知识再汇总。
2. 纯规则题不误走 NL2SQL；纯查数题不空跑 RAG（允许偶尔双路，但结论要相关）。
