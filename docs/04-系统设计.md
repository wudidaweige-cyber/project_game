## 一、系统架构设计

### 1.1 架构目标

- 业务数据查询（看板）与 AI 分析（Agent）职责分离，互不拖垮。
- Agent / MCP / RAG 可独立演进，便于后续扩展异常分析、策略分析、客服等能力。
- **前期原则：优先功能实现与端到端跑通**（看板 → MCP → RAG → Agent 串联），不追求 Docker/Nginx 部署形态。
- 依赖服务（PostgreSQL、Milvus 等）前期可用本机安装或任意现成实例；`data/` 用于模拟数据与知识样例，不强制容器卷映射。


### 1.5 运行与部署策略

#### 前期（当前重点）：本机跑通，不追求 Docker

- 后端：`uvicorn` / FastAPI 本机监听 **8888**。
- 前端：Vite 开发服务器；通过代理访问 `/api/v1`。
- PostgreSQL：本机安装或已有实例即可（不强制容器）。
- Milvus：做到 RAG 阶段再准备；可用本机/云托管，不阻塞看板与 NL2SQL 先行。
- Redis / Nginx / 应用镜像：**不做**，留到整体功能稳定之后。
- 验收标准：功能闭环可演示（看板有数、NL 能查、知识能问、Supervisor 能串），而非“一键 compose up”。

```text
[浏览器] → Vite 前端
              │ /api 代理
         FastAPI :8888
              ├─ PostgreSQL（本机）
              ├─ Milvus（RAG 阶段）
              └─ LLM API（外网）
```

#### 后期（功能跑通后，可选）

- 再用 Docker Compose 编排 PostgreSQL / Redis / Milvus，数据目录可映射到 `data/`。
- 前端 + 后端可打成应用镜像，Nginx 统一 80/443 反代 `/api/v1` → `8888`。
- 此阶段不纳入前期里程碑与验收阻塞项。

## 二、数据库设计

### 2.1 设计原则（对齐白板规范）

1. **表名前缀统一**：业务表 `ops_`；系统表 `sys_`；AI 表 `ai_`。
2. **审计字段每表必备**（除非纯日志只追加）：
   - `create_user_id`、`create_user_name`
   - `update_user_id`、`update_user_name`
   - `create_time`、`update_time`
3. **主键**：`VARCHAR(36)` UUID，避免自增 int，便于迁移与分库扩展。
4. **外键**：库内**不建物理外键**；关联在应用层逻辑维护；必要字段建索引。
5. **注释**：表、字段必须有 COMMENT（或等价迁移注释）。
6. **RAG**：向量在 Milvus；PostgreSQL 存 `chunk_id`、原文、文档类型、权限/可见性等元数据，查询时按元数据过滤。
7. **敏感字段**：账号凭证、支付信息等不入库明文进模型；库内可哈希/脱敏存储或禁止 AI 查询列。

## 三、接口设计

### 3.1 约定（对齐白板）

1. **先定目录结构**（见 1.6 `backend/app/api/v1/`），再按域拆路由。
2. **输入**：RESTful 路径 + Query/Path；**POST/PUT body 必须为 JSON**。
3. **输出**：统一 JSON：

```json
{
  "code": 200,
  "data": {},
  "message": "success"
}
```

| code | 含义 |
|---|---|
| 200 | 成功 |
| 400 | 参数错误 |
| 401 | 未认证 |
| 403 | 无权限 |
| 404 | 资源不存在 |
| 500 | 服务器错误 |
| 501 | 业务失败（如 SQL 安全拦截、Agent 失败） |

4. **版本与入口**：前端统一请求 **`/api/v1/...`**；开发期后端端口 **8888**。
5. **Nginx**：生产/演示统一路由；对外 80/443，例如 `https://ops.example.com/api/v1/dashboard/overview`。
6. **粒度**：接口按资源拆分，禁止巨型「万能接口」；均需注释；可先 **Mock** 再接真实服务。
7. **鉴权**：除登录外，Header 携带 Token（如 `Authorization: Bearer <token>`）。

### 3.2 路由模块划分

| 模块前缀 | 职责 | MVP |
|---|---|---|
| `/api/v1/auth` | 登录、当前用户 | P0 |

| `/api/v1/games` | 游戏列表/详情（轻量） | P0 |
