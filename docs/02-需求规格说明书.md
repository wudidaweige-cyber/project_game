# 软件需求规格说明书（SRS）

**项目名称：游戏平台账号租赁智能运营分析系统**  
**版本：V1.0**  
**文档性质：产品需求与开发验收基准**  
**依据文档：`docs/01-游戏平台账号租赁智能运营分析系统_项目开发需求前置文档_V1.0.md`**

---

## 1. 引言

### 1.1 项目背景

本系统面向游戏账号租赁平台的运营分析场景，建设一套集运营数据看板、自然语言数据分析、异常分析、运营知识库和智能运营辅助于一体的智能分析平台。

系统以 PostgreSQL 等业务数据为基础，结合 LLM、LangGraph、MCP 和 RAG，将传统的数据查询、业务分析和运营规则检索流程进行智能化整合，形成“业务数据 + 运营知识 + AI Agent”的分析闭环，使运营人员可通过自然语言完成数据查询、趋势分析、异常定位和运营规则查询，降低对人工 SQL 与重复性分析工作的依赖。

### 1.2 建设目标

- 建设统一的运营数据分析平台，集中展示 GMV、订单量、出租率、退款率等核心指标。
- 支持自然语言查询业务数据，由 AI Agent 完成问题理解、SQL 生成、数据查询与结果分析。
- 建设运营知识库，将 SOP、退款规则、账号管理规范、定价规则等纳入 RAG 检索。
- 对核心指标进行趋势与异常分析，并在必要时结合知识库给出处理参考。
- 结合业务数据与运营知识，提供运营策略分析与建议（第一阶段不直接改写业务数据）。
- 通过 LangGraph 与 MCP 建立可扩展的 Agent 工作流与业务工具调用体系。

### 1.3 文档约定

- **P0（Must Have）**：MVP 必须实现，否则无法完成可演示闭环。
- **P1（Should Have）**：重要能力，可在 MVP 稳定后迭代。
- **P2（Nice to Have）**：增强能力，优先级较低。
- 功能编号统一采用 `F + 两位数字`，例如 `F01`。
- 本文档中的“系统”均指游戏平台账号租赁智能运营分析系统。
- AI 分析结果属于辅助结论；第一阶段策略建议仅供参考，不得直接修改业务库写数据。

### 1.4 现有业务痛点（需求来源）

- 业务数据分散在游戏、账号、订单、用户、退款等表中，难以快速获得完整分析结论。
- 日常查询依赖人工编写 SQL，简单重复需求响应效率低。
- 传统 BI 侧重指标展示，对“为什么变化”和“如何处理”缺少进一步能力。
- 运营 SOP、退款规则、账号管理规范等资料分散，查找成本高。
- 数据分析与运营知识相互独立，难以形成“发现问题—分析原因—参考规则—给出建议”闭环。
- 核心指标异常主要依赖人工看报表，缺少统一异常分析能力。

## 2. 功能需求

### F01 用户与角色权限

**优先级：P0**

**描述：** 支持运营人员、数据分析人员、管理员等角色，按角色控制菜单、接口与数据访问范围，遵循最小权限原则。

**前置条件：** 用户已注册或由管理员开通账号。

**基本流程：**
1. 用户登录系统。
2. 系统加载角色与权限。
3. 按权限展示运营看板、AI 分析、知识库等功能入口。
4. 后端对业务 API 与 Agent 调用再次鉴权。

**异常处理：**
- 未认证 → 跳转登录。
- 无权限操作 → 返回 403，不返回敏感数据细节。

**验收标准：**
- 前端隐藏与后端鉴权同时生效。
- 不同角色可见的数据范围符合最小权限配置。

---

### F02 运营数据看板

**优先级：P0**

**描述：** 提供平台核心经营指标及趋势展示，支持按时间范围、游戏等维度筛选与分析。

**核心指标：** GMV、订单量、出租率、退款率、可出租账号数、活跃游戏数。

**前置条件：** 用户已登录且具备看板查看权限；业务/指标数据已就绪（含模拟数据）。

**基本流程：**
1. 用户进入运营驾驶舱。
2. 选择时间范围、游戏等筛选条件。
3. 系统返回核心指标卡片、趋势图与游戏排行。
4. 用户可进入指定游戏详情，查看账号、订单、价格、出租率及历史趋势。

**异常处理：**
- 筛选条件无数据 → 展示空态并提示调整条件。
- 指标计算服务异常 → 明确错误提示，不影响其他已加载模块展示。

**验收标准：**
- 可展示上述核心指标。
- 支持时间趋势与游戏维度排行（GMV、订单量、出租率、退款率等）。
- 支持指定游戏详情页（账号、订单、价格、出租率及历史趋势）。

---

### F03 AI 自然语言数据分析（NL2SQL）

**优先级：P0**

**描述：** 运营人员通过自然语言提出业务问题，系统自动完成问题理解、SQL 生成、数据库查询、数据分析并输出自然语言结论。

**示例问题：** “最近 30 天出租率下降最多的游戏有哪些”

**前置条件：** LLM Provider 可用；业务库可读；MCP/查询工具已注册。

**基本流程：**
1. 用户输入自然语言问题。
2. Supervisor/数据分析 Agent 理解意图并生成只读 SQL。
3. 对 SQL 做语法、表权限与危险操作检查。
4. 通过 MCP 或查询层执行 SELECT，获取结果集。
5. Agent 分析结果并返回自然语言结论（可附带关键表格/图表数据）。

**异常处理：**
- 问题无法映射到现有表结构 → 说明无法回答的原因并给出可改写建议。
- SQL 未通过安全检查 → 拒绝执行并记录原因。
- 查询超时或数据库异常 → 任务失败并提示可重试。

**验收标准：**
- 典型运营问题可走通：理解 → 安全 SQL → 查询 → 自然语言回答。
- 默认仅允许 SELECT；写操作一律拒绝。
- 会话/任务可追溯到所用 SQL（脱敏后）与结果摘要。

---

### F04 异常监控与分析

**优先级：P1**

**描述：** 针对 GMV、订单量、出租率、退款率及账号库存等核心指标进行异常识别，并从游戏、账号、订单等维度定位异常原因。

**前置条件：** 每日指标或可计算的趋势数据可用。

**基本流程：**
1. 用户发起异常分析，或系统基于指标波动触发分析任务。
2. 异常分析 Agent 识别异常指标与时间窗口。
3. 下钻至游戏/账号/订单等维度定位贡献因素。
4. 必要时调用知识 Agent 检索相关 SOP/规则。
5. 输出异常结论与参考处理建议。

**异常处理：**
- 指标数据不足 → 提示数据窗口不够，不编造异常。
- 下钻无显著贡献维度 → 明确说明“未定位到单一主因”。

**验收标准：**
- 能对至少一类核心指标给出异常判断与维度下钻结论。
- 分析过程与工具调用可追踪。

---

### F05 运营知识库与 RAG

**优先级：P0**

**描述：** 将运营 SOP、账号管理、退款、定价、风控等文档统一管理并向量化检索，支持自然语言问答，返回对应业务规则与参考内容。

**知识类型（第一阶段）：**
- 运营 SOP（上架、下架、异常订单处理等）
- 退款规则
- 账号管理规则
- 定价规则
- 风控规则

**前置条件：** 用户具备知识库管理或问答权限；Embedding/检索服务可用。

**基本流程：**
1. 上传或导入运营文档。
2. 解析、切分、向量化并写入向量库。
3. 用户提问或 Agent 发起检索。
4. 支持向量检索，并在架构允许时使用 Hybrid Search（如 BM25 + 向量）与 Rerank。
5. 将检索片段注入上下文，生成带依据的回答。

**异常处理：**
- 文档解析/向量化失败 → 标记失败并可重试。
- 检索无结果 → 明确说明知识库无依据，禁止伪造规则。

**验收标准：**
- 文档可管理、可检索。
- 问答能返回与问题相关的规则片段或摘要，并尽量标明来源文档。
- 第一阶段可用模拟文档完成 RAG 验证。

---

### F06 运营策略分析

**优先级：P1**

**描述：** 结合出租率、订单量、库存、价格、GMV 等数据，对游戏或账号运营情况进行分析并生成运营建议。

**约束：** 第一阶段仅提供分析与建议，**不直接修改**业务数据（价格、上下架状态等）。

**基本流程：**
1. 用户选择分析对象（游戏/账号集合）与时间范围。
2. 策略分析 Agent 通过 MCP 拉取指标与明细。
3. 必要时检索定价/运营规则知识。
4. 输出结构化建议（如调价观察、库存倾斜、活动建议等），供人工决策。

**异常处理：**
- 数据不足以支撑建议 → 说明限制条件。
- 建议涉及写操作 → 仅输出建议文案，不触发写接口。

**验收标准：**
- 能基于数据生成可读运营建议。
- 全链路无业务写库副作用。

---

### F07 Supervisor 与 Multi-Agent 工作流

**优先级：P0**

**描述：** 基于 LangGraph 构建 Supervisor 工作流，按用户问题将任务路由至专业 Agent，并汇总结果。

**推荐 Agent 职责：**

```text
Supervisor
 ├── 数据分析 Agent（NL2SQL / 指标查询）
 ├── 异常分析 Agent
 ├── 知识 Agent（RAG）
 └── 策略分析 Agent
```

**基本流程：**
1. 用户提出自然语言问题或选择分析场景。
2. Supervisor 理解意图并路由到一个或多个 Agent。
3. Agent 通过 MCP / RAG 获取数据或知识。
4. Supervisor 汇总分析结论返回前端。

**异常处理：**
- Agent 调用失败 → 按策略重试或终止，并返回可定位错误。
- 工具参数不合法 → 拒绝调用并记录。
- 工作流超时 → 标记失败，支持重试。

**验收标准（MVP）：**
- 至少串联 Supervisor + 数据分析 Agent + 知识 Agent。
- Agent 路由与工具调用可追踪。

---

### F08 MCP 业务工具调用

**优先级：P0**

**描述：** 通过 MCP 统一封装游戏、账号、订单及运营指标等业务查询工具，供 Agent 安全调用。

**工具范围（MVP 优先）：** 游戏查询、订单查询、GMV/出租率等指标查询；后续扩展账号库存、退款明细等。

**安全约束：**
- 工具默认只读。
- 不同 Agent 仅开放完成自身任务所需的工具集。

**验收标准：**
- MCP Server 可注册并被 Agent 调用。
- 工具调用有入参、出参摘要与耗时记录。
- 禁止通过工具执行写库或危险 SQL。

---

### F09 AI 分析会话与任务记录

**优先级：P0**

**描述：** 保存用户 AI 会话、任务状态、Agent 节点、工具/SQL 调用摘要与最终结论，支持问题追踪与调试。

**基本流程：** 创建会话/任务 → 记录执行节点 → 成功/失败落库 → 前端可回看。

**验收标准：**
- 可按用户、时间、任务类型查询执行记录。
- 记录中不得包含未脱敏的手机号、账号凭证、支付信息等敏感字段。

---

### F10 可观测性（LangSmith 等）

**优先级：P1**

**描述：** 记录 Agent、模型与工具调用链路，便于问题定位与效果优化。

**验收标准：**
- 开发/测试环境可接入 LangSmith 或同类链路追踪（可配置开关）。
- 关键错误能关联到任务/会话 ID。

## 3. 非功能需求

### 3.1 性能

- 普通业务数据查询：目标响应时间为秒级（P95 建议 < 3 秒，不含大范围报表导出）。
- 运营看板核心接口：在常规筛选条件下应可交互使用（P95 建议 < 2 秒）。
- AI 分析任务允许因模型推理产生延迟，宜异步或流式反馈进度，不要求同步秒级完成。
- AI 长任务不得阻塞普通看板 API。

### 3.2 可扩展性

- Agent、MCP 工具、RAG 检索模块保持相对独立，便于后续增加客服、营销、风控等能力。
- 模型通过 OpenAI Compatible 等方式接入，便于切换 Qwen、DeepSeek 等厂商。

### 3.3 可维护性

- 模块化设计：业务 API、Agent 工作流、MCP、RAG、看板查询职责分离。
- 配置与代码分离；密钥与连接串通过环境变量管理。
- 统一日志、异常处理与接口规范。

### 3.4 可观测性

- 记录 Agent 节点、Tool/MCP 调用、模型与耗时。
- 支持 LangSmith 等链路追踪（P1）。
- 关键错误包含可定位的任务/会话 ID。

### 3.5 部署

- **前期（功能阶段）：** 以本机进程跑通为主（后端 FastAPI、前端 Vite、PostgreSQL 本机或已有实例），不将 Docker/Nginx 作为验收阻塞项。
- **后期（工程化）：** 再支持 Docker 化部署与 Compose 编排，便于环境迁移与演示交付。
- Redis、完善 Docker Compose 等在核心功能闭环稳定后再补。

### 3.6 可用性

- 支持 Chrome、Edge 近两个主要版本。
- AI 任务失败应给出明确原因，并支持重试（在安全策略允许时）。

## 4. 安全需求

- AI 数据分析默认**仅允许 SELECT**，禁止 INSERT、UPDATE、DELETE、DROP、ALTER、TRUNCATE 等写操作。
- 对 AI 生成 SQL 进行语法、表权限及危险操作检查，避免模型错误调用数据库。
- 根据用户角色控制数据访问范围，遵循最小权限原则。
- 手机号、账号凭证、支付信息等敏感数据不得直接进入模型上下文，必要时脱敏。
- 不同 Agent 仅开放完成自身任务所需的 MCP 工具，限制无关数据访问。
- API Key、数据库凭证不得写入代码仓库或前端明文展示。
- 策略分析等能力不得绕过人工直接改写业务数据（第一阶段硬约束）。

## 5. 数据需求

### 5.1 业务数据模型（第一阶段）

| 数据类型 | 主要内容 | 用途 |
| -------- | -------- | ---- |
| 游戏数据 | 游戏名称、分类、平台、状态 | 游戏维度分析 |
| 账号数据 | 账号、游戏、价格、状态、出租次数 | 账号及库存分析 |
| 用户数据 | 用户、注册时间、用户类型、状态 | 用户及订单分析 |
| 订单数据 | 订单、用户、账号、游戏、价格、时长、状态 | GMV、订单及出租率分析 |
| 退款数据 | 订单、退款金额、退款原因、状态 | 退款率及异常分析 |
| 运营指标 | 日期、GMV、订单量、出租率、退款率等 | 趋势及异常分析 |

### 5.2 逻辑实体（实现参考）

| 实体名 | 描述 | 关键字段（示例） |
|---|---|---|
| Game | 游戏 | id, name, category, platform, status |
| Account | 可租赁账号 | id, game_id, price, status, rent_count |
| User | 平台用户 | id, register_at, user_type, status |
| Order | 租赁订单 | id, user_id, account_id, game_id, price, duration, status |
| Refund | 退款 | id, order_id, amount, reason, status |

| KnowledgeChunk | 文档切片/向量 | id, document_id, content, embedding |

### 5.3 模拟数据要求

- 第一阶段可使用 Python 生成模拟业务数据，用于开发与 Agent 能力验证。
- 数据规模应能体现趋势、排行与异常分析等场景。

### 5.4 知识库数据需求

- 第一阶段可使用内部模拟文档构建知识库，重点验证 RAG 检索与回答准确性。
- 文档类型覆盖 SOP、退款、账号管理、定价、风控等。

| 名称 | 用途 | 说明 |

## 7. 核心业务流程

```text
运营人员
  → 自然语言问题 / 看板交互
  → Supervisor
  → 专业 Agent（数据分析 / 异常 / 知识 / 策略）
  → MCP（PostgreSQL 等） / RAG（运营文档）
  → 数据或知识
  → 分析汇总
  → 运营结论
```

- 数据分析场景：主要通过 MCP 调用 PostgreSQL 等业务数据。
- 知识问答场景：通过 RAG 检索运营文档。
- 复杂问题：由 Supervisor 负责任务路由与结果汇总。

## 8. 约束与假设

### 8.1 技术约束

| 层级 | 技术选型 |
|---|---|
| 前端 | Vue、ECharts（运营驾驶舱与 AI 分析交互） |
| 后端 | Python、FastAPI |
| Agent | LangChain、LangGraph、Supervisor、多 Agent |
| 模型 | Qwen、DeepSeek 或其他 OpenAI Compatible 模型 |
| 数据库 | PostgreSQL；Redis（缓存，可后置） |
| RAG | Milvus、Embedding、BM25、Hybrid Search、RRF、Rerank |
| 工具调用 | MCP、Function Calling |
| 工程化 | Git；LangSmith / Docker（功能跑通后） |

未经明确要求，不得随意替换上述核心技术栈。

### 8.2 假设条件

- 开发与演示阶段可使用模拟业务数据与模拟运营文档。
- 客户或部署方可提供可用的 LLM / Embedding API。
- AI 生成的 SQL 与分析结论不保证绝对正确，必须经过安全校验；关键运营动作由人工决策。
- 第一阶段不以对接真实游戏平台生产写接口为目标。

## 9. MVP 开发范围

第一阶段以“可运行、可演示、可扩展”为目标，优先完成：

1. 建立游戏、账号、用户、订单、退款及每日指标等核心数据模型。
2. 完成运营数据看板：核心指标、趋势与游戏排行。
3. 完成自然语言数据查询：NL2SQL → 数据库 → 分析 → 自然语言回答。
4. 搭建 MCP Server，提供游戏、订单、GMV、出租率等查询工具。
5. 完成基础 RAG 知识库，实现运营文档检索与问答。
6. 使用 LangGraph 将 Supervisor、数据分析 Agent 与知识 Agent 串联。
7. 前期验收以「功能实现 + 端到端本机跑通」为准；异常监控、策略分析、LangSmith、Redis、Docker 部署等在闭环稳定后再补。

---

## 10. 预期成果

最终形成一套面向游戏平台账号租赁运营场景的智能分析系统，实现从业务数据采集、指标展示、自然语言查询、知识检索到异常分析与运营建议的完整闭环，并体现数据分析业务能力与 RAG、Agent、MCP、LangGraph 等 AI 应用技术的结合。

## 11. 附录：术语表

| 术语 | 定义 |
|---|---|
| GMV | 成交总额（Gross Merchandise Volume），本系统指租赁订单相关成交金额口径 |
| 出租率 | 可出租账号中实际出租占比或约定统计口径下的出租效率指标 |
| NL2SQL | 将自然语言问题转换为 SQL 查询的能力 |
| RAG | Retrieval-Augmented Generation，检索增强生成 |
| MCP | Model Context Protocol，向模型标准化提供工具与上下文 |
| LangGraph | 用于构建可编排 Agent 工作流的框架 |
| Supervisor | 负责任务理解、路由与结果汇总的主控 Agent |
| Hybrid Search | 向量检索与关键词检索（如 BM25）等融合检索 |
| Rerank | 对初检结果重排序以提升相关性 |
| Human-in-the-loop | 人工确认环节；本项目第一阶段策略建议不自动落库 |
