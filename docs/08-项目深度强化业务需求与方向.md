## 0. 企业级完成定义（Definition of Done）

完成本文 **Gate A + Gate B** 后，本项目可在简历中定位为：

> **B 端智能运营分析平台（可控数据智能 + 决策闭环）**  
> 而非「LangGraph + RAG 聊天 Demo」。

### 0.1 什么叫「企业级深度」（本项目语境）

面试官认可的「企业级」通常看这 6 条是否同时成立：

| # | 维度 | 必须可证明 |
|---|------|------------|
| 1 | 业务闭环 | 发现问题 → 分析 → 建议 → 人审工单 → 执行回写 → 效果评估 |
| 2 | 数据可信 | 指标有唯一口径；有接入/对账；脏数据可发现 |
| 3 | 安全可控 | 身份鉴权、RBAC、租户隔离、SQL 只读守卫、写操作审批、审计、脱敏 |
| 4 | AI 可治理 | 路由/工具/Token 可观测；拒答与幻觉策略；评测集与回归 |
| 5 | 可交付 | Docker Compose 可起；配置与密钥分离；关键路径有自动化测试 |
| 6 | 可讲述 | 有架构图、Demo 脚本、边界说明；能讲清 Trade-off |

### 0.2 两道门禁（简历可用性）

#### Gate A —「可写进简历的企业向项目」（最低企业级）

### 2.1 企业级主业务链路（必须能 Demo）


**硬约束（写入 CLAUDE.md / 编码军规）：**

1. Agent **永不**直接 `UPDATE/DELETE` 业务表。  
2. 一切业务变更只通过 **工单状态机 + 执行器**。  
3. 一切指标展示/Agent 用数必须走 **口径服务或语义视图**。  
4. 一切查询必须带 **tenant_id**（超管切换除外并记审计）。

## 3. 角色、权限与租户模型

### 3.1 角色（F25）

| 角色 | 代码 | 典型权限 |
|------|------|----------|
| 平台超管 | `super_admin` | 切换租户、系统配置、查看全量审计 |
| 租户管理员 | `tenant_admin` | 用户、知识、口径、告警规则、审批配置 |
| 运营主管 | `ops_lead` | 工单审批、告警处理、策略确认 |
| 运营专员 | `operator` | 看板、问答、创建/提交工单、知识只读 |
| 数据分析师 | `analyst` | 看板、问数、导出（脱敏）、无审批权 |
| 只读访客 | `viewer` | 看板只读（演示可选） |

MVP 企业级可先落地 4 个：`tenant_admin` / `ops_lead` / `operator` / `analyst`（`admin` 映射为 `tenant_admin`）。

### 3.2 权限点（资源 × 动作）

```text
dashboard:read
agent:ask
agent:ask_write_intent   （会被拒，但要审计）
knowledge:read | knowledge:write
ticket:create | ticket:submit | ticket:approve | ticket:execute
alert:read | alert:ack | alert:rule_write
metric:read | metric:define_write
audit:read
tenant:switch
export:run
system:config
```

**验收：** 前端隐按钮 + 后端 403 双检；用 pytest 覆盖越权矩阵（至少 12 条用例）。

### 3.3 多租户（F24）

- 所有业务表、知识表、AI 表、工单/告警表增加 `tenant_id varchar(32) NOT NULL` + 索引。  
- Repository / MCP / 口径查询 **强制** `WHERE tenant_id = :tid`。  
- JWT Claims：`sub, role, tenant_id, permissions[]`。  
- Seed：至少 2 个租户、差异化游戏与知识，Demo「串租失败」。

**反例测试（必写）：**  
构造 SQL `SELECT * FROM ops_order` 不带租户 → MCP 层拒绝或自动注入租户谓词（二选一，文档写死策略）。

## 4. 业务需求详设（企业级增量）

### 4.1 F20 运营动作工单与人审闭环（P0 · Gate A）

#### 业务规则

| 项 | 规则 |
|----|------|
| 来源 | 策略/异常 Agent 结构化输出，或运营手工创建 |
| 动作类型 | `price_watch` / `account_offline` / `inventory_tilt` / `promo_suggest` / `refund_process_ref` / `other` |
| 风险等级 | `low` / `medium` / `high`；`high` 必须 `ops_lead` 审批 |
| 状态机 | `draft → pending_review → approved\|rejected → executing → done\|failed`；`cancelled` 可自 draft/pending |
| 非法流转 | 直接抛领域错误；全量写 `sys_audit_log` |
| 关联 | `source_ai_task_id`、`source_session_id` 可空但 Demo 路径必填 |

#### 建议表结构（回写 docs/04）

**`ops_ticket`**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | varchar(32) | PK |
| tenant_id | varchar(32) | 租户 |
| title | varchar(200) | 标题 |
| action_type | varchar(64) | 动作类型 |
| risk_level | varchar(16) | 风险 |
| status | varchar(32) | 状态 |
| target_type | varchar(32) | game/account/global |
| target_id | varchar(32) | 可空 |
| payload_json | jsonb | 建议参数（调价幅度、账号列表等） |
| ai_summary | text | AI 摘要 |
| source_ai_task_id | varchar(32) | 关联任务 |
| created_by / updated_by | varchar(32) | 审计 |
| reviewer_id | varchar(32) | 审批人 |
| review_comment | text | 审批意见 |
| executed_at / closed_at | timestamptz | 时间 |
| create_time / update_time / is_deleted | 标准审计字段 | |

**`ops_ticket_event`**：状态变更流水（who/when/from/to/comment）。

#### API（示例）

```text
POST   /api/v1/tickets                 创建（可从 task_id 生成）
GET    /api/v1/tickets                 列表（状态/风险/游戏筛选）
GET    /api/v1/tickets/{id}
POST   /api/v1/tickets/{id}/submit     draft → pending_review
POST   /api/v1/tickets/{id}/approve
POST   /api/v1/tickets/{id}/reject     body.reason 必填
POST   /api/v1/tickets/{id}/execute    人工确认或调用 Adapter
POST   /api/v1/tickets/{id}/cancel
GET    /api/v1/tickets/{id}/events
```

#### 结构化 Action（Agent 输出契约）

```json
{
  "actions": [
    {
      "action_type": "account_offline",
      "risk_level": "high",
      "target_type": "account",
      "target_ids": ["acc_xxx"],
      "params": {"reason": "refund_rate_spike", "suggest_days": 7},
      "rationale": "近7日退款率上升且命中风控规则[2]"
    }
  ]
}
```

策略 Agent 必须尽量输出该 JSON；前端「一键生成工单」解析失败则进入手工编辑。

#### 验收

1. 策略问答 → 生成 ≥1 条 draft 工单。  
2. operator 不能 approve；ops_lead 可。  
3. reject 无 reason → 400。  
4. 状态机单测覆盖全部合法/非法边。  
5. 审计可查每一次流转。

### 4.2 F21 效果回评与反馈闭环（P0 · Gate A）

#### 规则

- 工单 `done` 后进入评估队列。  
- 默认窗口：执行前 `N` 天 vs 后 `N` 天（配置 `IMPACT_WINDOW_DAYS`，默认 7）。  
- 对比指标：GMV、订单量、出租率、退款率（必须走口径服务）。  
- 人工标签：`effective` / `ineffective` / `inconclusive`。  
- 干扰因子可选标记：大促、版本更新、供给变化。

#### 表 `ops_ticket_impact`

| 字段 | 说明 |
|------|------|
| ticket_id / tenant_id | 关联 |
| baseline_json / treatment_json | 窗口指标快照 |
| delta_json | 变化幅度 |
| label / label_by / label_comment | 人工打标 |
| computed_at | 计算时间 |

#### API

```text
GET  /api/v1/tickets/{id}/impact
POST /api/v1/tickets/{id}/impact/recompute
POST /api/v1/tickets/{id}/impact/label
```

#### 验收

- Demo 脚本可「快进」日期或写入对比快照，展示效果卡片。  
- 打标写入后可在工作台/工单详情看见。  
- 与源 `ai_task` 三方互链。

### 4.3 F22 指标口径中心与数据接入（P0 · Gate A）

#### 口径字典（唯一真源）

表 `ops_metric_def`：

| 字段 | 说明 |
|------|------|
| code | 如 `gmv` / `rent_rate` / `refund_rate` |
| name / description | 中文名与业务解释 |
| formula_sql | 或指向语义视图名 |
| time_grain | day |
| filters_json | 订单状态白名单等 |
| version / effective_from / effective_to | 版本化 |
| owner | 口径负责人 |

**语义视图（建议）**

```text
vw_metric_daily_tenant   -- 供看板与 Agent 优先查询
vw_order_fact_safe       -- 已脱敏、已过滤非法状态
```

#### 数据接入

1. **Batch Import API**：`POST /api/v1/ingest/orders`（CSV/JSON，限 tenant_admin）。  
2. **对账任务** `ops_reconcile_run`：订单聚合 vs `ops_daily_metric`，差异率 > 阈值 → 告警。  
3. 提供「脏数据样例包」：`data/fixtures/dirty_orders.csv`。

#### 脱敏

配置 `SENSITIVE_FIELDS`：手机号、账号密码/cookie、支付信息；进入 LLM / 日志 / 导出前统一 `mask()`。

#### 验收

- 修改口径版本后，看板与 Agent 数字一致。  
- 脏数据导入触发对账失败记录。  
- NL2SQL Prompt 明确「优先 vw_metric_*，禁止无 LIMIT 扫事实表」。

### 4.4 F23 Agent 可观测工作台（P0 · Gate A）

#### 页面能力

1. 任务列表：租户、路由、状态、耗时、费用估算、失败原因码。  
2. 任务详情时间线：router → agents → tools → sql → rag hits → synthesize。

#### 数据

扩展 `ai_agent_execution`：`token_input` / `token_output` / `cost_estimate` / `error_code` / `tool_name`。

#### 验收

一次 `anomaly_knowledge` 全链路可回放；研发 3 分钟内定位 Guard 拦截。

### 4.6 F26 异常监控与告警（P0 · Gate A）

#### 规则表 `ops_alert_rule`

- metric_code、comparator、threshold、window_days、scope（global/game）、enabled。

#### 事件表 `ops_alert_event`

- status：`open` / `acked` / `closed`  
- 一键：`POST /api/v1/alerts/{id}/ask` → 创建带上下文的 session/task。

#### 调度

- APScheduler / 进程内定时（演示 1 分钟）；生产可换 cron。

#### 验收

### 4.10 Gate B 选修详设（摘要）

#### F29 外部中台 Adapter

- 接口：`IngestAdapter.sync_orders(day)` / `ExecutionAdapter.execute(ticket)`。  
- 提供 `MockLeaseMidPlatform`：内存/文件模拟外部系统。  
- 工单 execute 走 Adapter；失败可重试；记录外部请求 id（幂等键）。

#### F30 定价模拟器

- 输入：游戏、调价 ±X%、窗口。  
- 输出：基于历史弹性的粗估出租率/GMV 区间 + 风险提示。  
- 结果可写入工单 `payload_json.simulation`。

#### F31 账号风险评分

- 特征：退款率、投诉次数、短时多租、价格异常。  
- 输出 0–100 分与因子贡献；策略 Agent 可引用。

#### F35 成本与配额

- 每租户日 Token 配额；超限 `QUOTA` 错误码。  
- 管理台看消耗排行。

#### F36 幂等与 Outbox

- `ops_outbox` 表保证「审批通过 → 执行消息」至少一次投递。  
- execute API 支持 `Idempotency-Key`。
