**游戏平台账号租赁智能运营分析系统**

项目开发需求前置文档 · V1.0

# 一、项目概述

本项目面向游戏账号租赁平台的运营分析场景，建设一套集运营数据看板、自然语言数据分析、异常分析、运营知识库和智能运营辅助于一体的智能分析系统。系统以 PostgreSQL 等业务数据为基础，结合 LLM、LangGraph、MCP 和 RAG 技术，将传统的数据查询、业务分析和运营规则检索流程进行智能化整合。

项目最终形成“业务数据 + 运营知识 + AI Agent”的分析闭环，使运营人员能够通过自然语言完成数据查询、趋势分析、异常定位和运营规则查询，降低对人工 SQL 查询和重复性数据分析工作的依赖。

# 二、项目需求背景

游戏平台在账号、订单、用户、游戏、退款等业务运行过程中会持续产生大量运营数据。传统运营分析通常依赖数据库查询、Excel/BI报表以及人工经验完成，数据查询和分析过程存在一定的人工成本。

与此同时，平台的运营 SOP、退款规则、账号管理规范、定价规则等业务知识通常分散在不同文档中，数据分析结果与业务规则之间缺少有效关联。因此，需要建设统一的智能运营分析系统，将数据分析能力与业务知识检索能力结合起来。

# 三、现有业务痛点

- 业务数据分散在游戏、账号、订单、用户、退款等不同数据表中，运营人员难以快速获得完整分析结果。

- 日常数据查询较多依赖数据分析人员编写 SQL，简单重复的数据需求响应效率较低。

- 传统 BI 主要负责展示指标，对于“为什么变化”和“应该如何处理”缺少进一步分析能力。

- 运营 SOP、退款规则、账号管理规范等资料分散，业务人员查找和确认规则成本较高。

- 数据分析与运营知识相互独立，难以形成从“发现问题—分析原因—参考规则—给出建议”的完整闭环。

- 核心指标异常主要依赖人工查看报表发现，缺少统一的异常分析能力。

# 四、项目建设目标

- 建设统一的游戏平台运营数据分析平台，集中展示 GMV、订单量、出租率、退款率等核心指标。

- 支持自然语言查询业务数据，通过 AI Agent 自动完成问题理解、SQL 生成、数据查询和结果分析。

- 建设运营知识库，将平台 SOP、运营规则、退款规则、定价规则等内容统一纳入 RAG 检索体系。

- 通过异常分析能力，对 GMV、订单量、出租率、退款率等指标进行趋势及异常分析。

- 结合业务数据与运营知识，为运营人员提供数据分析和运营策略参考。

- 通过 LangGraph 和 MCP 建立可扩展的 Agent 工作流及业务工具调用体系。

# 五、功能需求

## 5.1 运营数据看板

提供平台核心经营指标及趋势展示，支持按时间范围、游戏等维度进行筛选和分析。

- 核心指标：GMV、订单量、出租率、退款率、可出租账号数、活跃游戏数。

- 趋势分析：支持查看核心指标的时间变化趋势。

- 游戏分析：支持游戏 GMV、订单量、出租率、退款率等排行榜。

- 游戏详情：查看指定游戏的账号、订单、价格、出租率及历史趋势。

## 5.2 AI 自然语言数据分析

运营人员可通过自然语言提出业务问题，例如“最近30天出租率下降最多的游戏有哪些”，系统自动完成问题理解、SQL 生成、数据库查询、数据分析并输出自然语言结论。

## 5.3 异常监控与分析

针对 GMV、订单量、出租率、退款率及账号库存等核心指标进行异常识别，并进一步从游戏、账号、订单等维度定位异常原因。

## 5.4 运营知识库与 RAG

将运营 SOP、账号管理、退款、定价、风控等文档进行统一管理和向量化检索，支持基于自然语言的问题查询，并返回对应业务规则和参考内容。

## 5.5 运营策略分析

结合出租率、订单量、库存、价格、GMV 等数据，对游戏或账号的运营情况进行分析，并生成运营建议。第一阶段仅提供分析和建议，不直接修改业务数据。

## 5.6 Multi-Agent 与 MCP

基于 LangGraph 构建 Supervisor 工作流，根据用户问题将任务路由至数据分析 Agent、异常分析 Agent、知识 Agent 和策略分析 Agent；通过 MCP 统一封装游戏、账号、订单及运营指标等业务查询工具。

# 六、非功能需求

- 性能：普通业务数据查询目标响应时间控制在秒级；AI 分析任务允许根据模型推理复杂度产生一定延迟。

- 可扩展性：Agent、MCP 工具、RAG 检索模块应保持相对独立，便于后续增加客服、营销、风控等能力。

- 可维护性：采用模块化设计，配置与代码分离，并统一日志、异常处理和接口规范。

- 可观测性：通过 LangSmith 等工具记录 Agent、模型和工具调用链路，便于问题定位和效果优化。

- 部署：前期以本机进程跑通功能为主，不追求 Docker；功能稳定后再做 Docker 化，便于测试与环境迁移。

# 七、安全需求

- AI 数据分析默认仅允许执行 SELECT 类查询，禁止 INSERT、UPDATE、DELETE、DROP、ALTER、TRUNCATE 等写操作。

- 对 AI 生成的 SQL 进行语法、表权限及危险操作检查，避免模型错误调用数据库。

- 根据用户角色控制数据访问范围，遵循最小权限原则。

- 手机号、账号凭证、支付信息等敏感数据不得直接进入模型上下文，必要时进行脱敏处理。

- 不同 Agent 仅开放完成自身任务所需的 MCP 工具，限制无关数据访问。

# 八、数据需求

系统第一阶段主要建设以下业务数据模型：

| 数据类型 | 主要内容                                 | 用途                  |
| -------- | ---------------------------------------- | --------------------- |
| 游戏数据 | 游戏名称、分类、平台、状态               | 游戏维度分析          |
| 账号数据 | 账号、游戏、价格、状态、出租次数         | 账号及库存分析        |
| 用户数据 | 用户、注册时间、用户类型、状态           | 用户及订单分析        |
| 订单数据 | 订单、用户、账号、游戏、价格、时长、状态 | GMV、订单及出租率分析 |
| 退款数据 | 订单、退款金额、退款原因、状态           | 退款率及异常分析      |
| 运营指标 | 日期、GMV、订单量、出租率、退款率等      | 趋势及异常分析        |

第一阶段可使用 Python 生成模拟业务数据，用于完成系统开发、Agent 查询和分析能力验证；数据规模应能够体现趋势、排行和异常分析等场景。

# 九、知识库数据需求

- 运营 SOP：账号上架、下架、异常订单处理等流程。

- 退款规则：退款条件、退款原因及处理流程。

- 账号管理规则：账号发布、维护及违规处理规范。

- 定价规则：账号定价、价格调整及活动策略。

- 风控规则：异常账号及违规行为处理规范。

- 第一阶段可使用内部模拟文档构建知识库，重点验证 RAG 检索与回答准确性。

# 十、核心业务流程

系统核心流程如下：

**运营人员 → 自然语言问题 → Supervisor → 专业 Agent → MCP / RAG → 数据或知识 → 分析 → 运营结论**

其中，数据分析场景主要通过 MCP 调用 PostgreSQL 等业务数据；知识问答场景通过 RAG 检索运营文档；复杂问题由 Supervisor 负责任务路由和结果汇总。

# 十一、技术架构

- 前端：Vue、ECharts，用于运营驾驶舱和 AI 分析交互。

- 后端：Python、FastAPI，提供业务 API 和 Agent 服务。

- Agent：LangChain、LangGraph、Supervisor、多 Agent 工作流。

- 模型：Qwen、DeepSeek 或其他 OpenAI Compatible 模型。

- 数据库：PostgreSQL，存储平台业务及分析数据；Redis 用于缓存等场景。

- RAG：Milvus、Embedding、BM25、Hybrid Search、RRF、Rerank。

- 工具调用：MCP、Function Calling。

- 工程化：Git；LangSmith / Docker 在功能跑通后按需引入。

# 十二、MVP 开发范围

第一阶段以“可运行、可演示、可扩展”为目标，优先完成：

1. 建立游戏、账号、用户、订单、退款及每日指标等核心数据模型。

2. 完成运营数据看板，展示核心指标、趋势和游戏排行。

3. 完成自然语言数据查询，实现 NL2SQL → 数据库 → 分析 → 自然语言回答。

4. 搭建 MCP Server，提供游戏、订单、GMV、出租率等查询工具。

5. 完成基础 RAG 知识库，实现运营文档的检索与问答。

6. 使用 LangGraph 将 Supervisor、数据分析 Agent 和知识 Agent 串联起来。

7. 前期验收侧重功能实现与整体跑通（本机即可）；MVP 稳定后，再逐步增加异常监控、策略分析、LangSmith、Redis 和 Docker 等能力。

# 十三、项目预期成果

最终形成一套面向游戏平台运营场景的智能分析系统，实现从业务数据采集、指标展示、自然语言查询、知识检索到异常分析和运营建议的完整闭环。项目重点体现数据分析业务能力与 RAG、Agent、MCP、LangGraph 等 AI 应用技术的结合。
