# 退款规则

**文档类型：** 退款规则  
**适用角色：** 客服、运营、财务（只读参考）  
**版本：** 模拟 V1.0

---

## 1. 总则

1. 退款以订单为单位发起，关联原租赁订单。
2. 已批准退款金额不得超过订单实付金额。
3. 退款原因需结构化记录，便于退款率分析。

## 2. 可退款情形

| 情形 | 是否可退 | 建议比例 |
|------|----------|----------|
| 支付后账号无法交付 | 是 | 100% |
| 租赁开始后 15 分钟内账号故障且平台责任 | 是 | 100% |
| 中途封禁/顶号（平台或供应商责任） | 是 | 按剩余时长比例 |
| 与描述严重不符（经核实） | 是 | 50%–100%（视情节） |
| 用户主观不喜欢/买错 | 视时长 | 未开始可退；已开始原则上不退 |
| 用户违规导致封禁 | 否 | 0% |

## 3. 不可退款情形

- 租赁已正常完成且无投诉时效内异议
- 用户分享账号导致的损失
- 超出投诉时效（模拟：订单结束后 48 小时）
- 恶意套利、设备农场等风控认定场景

## 4. 退款流程

1. 用户或客服发起退款申请（状态：`applying`）。
2. 运营/客服审核证据。
3. 通过则状态 `approved` 并记录退款时间、金额、原因。
4. 拒绝则状态 `rejected` 并注明理由。
5. 退款完成后，相关异常账号按 SOP 维护或下架。

## 5. 与指标口径的关系（演示约定）

- 退款率可按「退款订单数 / 订单数」或「退款金额 / GMV」统计，看板与分析需沿用同一口径。
- 本模拟环境种子数据中，部分游戏在特定日期会抬高退款率，用于异常演示。

## 6. 话术要点

- 告知用户处理时限与结果，不承诺无法兑现的即时到账时间。
- 不向用户泄露账号凭证与内部供应商信息。
