# 异常订单处理 SOP

**文档类型：** 运营 SOP  
**适用角色：** 运营、客服、风控协同  
**版本：** 模拟 V1.0

---

## 1. 异常订单定义

出现以下任一情况，视为异常订单：

- 支付成功但账号无法登录
- 租赁中途账号被顶号/封禁
- 用户投诉与商品描述严重不符
- 系统状态卡在 `pending` / `refunding` 超过阈值
- 短时间内同一用户对同一游戏高频下单又退款

## 2. 处理原则

1. **先保障用户体验，再追责内部原因。**
2. 证据留存：订单号、时间线、账号状态变更、沟通记录。
3. 涉及退款必须符合《退款规则》。

## 3. 处理流程

### 3.1 受理（0–15 分钟）

1. 定位订单号、游戏、账号、用户。
2. 确认订单当前状态与是否已开始计时。
3. 初步判定：账号侧问题 / 用户侧问题 / 系统问题。

### 3.2 处置

| 类型 | 动作 |
|------|------|
| 账号无法登录且责任在平台 | 立即换号或全额退款，账号转维护 |
| 中途封禁 | 按已消费时长折算，剩余时长退款；账号冻结送检 |
| 描述不符 | 可协商补差、换号或按规则退款 |
| 用户恶意刷退 | 标记用户，升级风控，不轻易全额退 |

### 3.3 关单

1. 更新订单状态为 `finished` / `cancelled` 或进入退款终态。
2. 写明处理结论与责任归属（平台/用户/供应商）。
3. 如需，触发账号下架或风控工单。

## 4. 升级条件

- 单日同游戏异常订单占比超过 5%
- 涉及支付资损或疑似盗号
- 媒体/投诉升级风险

升级后同步运营负责人与风控。

## 5. 时效要求（模拟口径）

- 普通异常：2 小时内给出处理方案
- 紧急（无法登录/封禁）：30 分钟内响应
